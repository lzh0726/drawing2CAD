# 按需 GPU 建模服务

已于 2026-10-25 完成部署与真实验证。此文替代先前“模型常驻 GPU”的运行说明。

页面和 CPU 接口保持运行，空闲时不加载模型、不占用 GPU。
点击开始建模后，本地任务顺序排队；远端检查显存、利用率和计算进程，连续两次确认空闲后启动独立推理进程。
模型生成代码后，该进程退出释放 CUDA 上下文，再由 Bubblewrap 隔离执行 CAD 并返回 STEP。
本地继续生成 STL 供页面预览，已有结果始终保留。

## 等待与取消

- 最多等待空闲 GPU 5 分钟；超时保留图纸并提示稍后重试。
- 单次模型加载与生成最多 240 秒，超时结束本项目的推理子进程。
- 页面显示等待 GPU、加载与生成、后续 CAD 检查等事件。
- 取消或请求断开会结束等待，并清理本次模型子进程。
- CPU 网关异常退出时，模型子进程通过 Linux 父进程退出信号终止。
- 项目内采用互斥锁避免与本项目训练启动器竞争。其他用户仍可能在检查之后启动任务；跨用户原子分配须依赖管理员调度系统。

## 验证结果

- 按需等待、取消与子进程超时清理：3 项测试通过。
- 前后端回归：30 项通过，1 项 Docker 条件跳过。
- 真实建模任务 dbeb212382904aedb5d55cd59d3f61e3 完成，STEP 17028 字节、STL 12 个三角形。
- 推理期间 GPU 1 临时约 17415 MiB；结束后无 server.inference_once 进程，接口保持在线且 model_state=idle。
- 结束后 GPU 1 的 667 MiB 属于其他项目进程，不是本项目残留。
- 真实排队取消任务 ebf0a36aecac4dbf91d4c9e1a42cc50d 验证通过，远端恢复 idle。
- 修复数据库打开时误恢复任务的副作用：只在实际服务启动时恢复中断任务，测试导入不会更改在运行任务。

## 日常使用

打开 http://127.0.0.1:8000/ ，上传图纸并开始建模。
保持本地后端、SSH 隧道和远端 CPU 网关在线即可；无需手工常驻加载模型。
服务器重启后，在项目根目录运行 `.venv-service/bin/python tools/start_online.py` 启动 CPU 网关。
`/health` 的 model_loaded=false 在按需模式下是正常的，需结合 status=ok、mode=on_demand 和 model_state 查看状态。

本次验证了真实接口与几何产物，未进行浏览器画面的人工视觉验收；几何有效性不等于图纸还原准确。
