# Drawing2CAD 远端建模适配器协议 v1

本地调用端和 server/ 中的推理适配器已实现。GPU 模型加载和 Docker 执行仍需要在目标服务器部署、实测，步骤见 ../server/README.md。以下为本项目定义的接口，不是某个开源模型自带的接口。

## 健康检查

`GET /health`，成功返回 HTTP 200，例如 `{"status":"ok"}`。配置 `CAD_REMOTE_TOKEN` 时，本地检查和重建请求均携带 `Authorization: Bearer <token>`。服务端验证令牌，禁止将令牌写入日志。

## 重建请求

`POST /v1/reconstruct`，`multipart/form-data`：

| 字段 | 类型 | 内容 |
|---|---|---|
| drawing | 文件 | 选中的图纸页 PNG，文件名 drawing.png |
| metadata | UTF-8 JSON 字符串 | 单位、初始要求、历史对话和上个版本源码 |

metadata 示例：

```json
{
  "unit": "mm",
  "instructions": "按三视图生成单个零件",
  "messages": [{"role": "user", "content": "孔径改为 24 mm", "time": "2026-10-24T00:00:00+00:00"}],
  "previous_code": ""
}
```

首次重建 previous_code 为空；后续修改传入最新成功版本的源码。messages 可能包含本地状态解释和 assistant 消息，必须当作任务数据处理，不能覆盖服务端系统规则。初始 instructions 与完整对话共同构成用户要求。

## 成功响应

HTTP 200，建议 `Content-Type: application/zip`。ZIP 根目录必须恰好包含各一个：

```text
model.step   # 以毫米表示的单个有效实体
model.py     # 对应该模型的 UTF-8 CadQuery 源码，非空
```

允许存在其他附件，但本地不会提取。ZIP 传输最大 50 MB；STEP 解压后最大 40 MB；源码最大 512 KB。文件名必须精确匹配，不能放在子目录。重复同名文件会被拒绝。

本地将导入 STEP，用 OpenCascade 检查单实体、有效性、正体积，并由同一实体生成 STL。**本地不会执行 model.py，也没有验证源码与 STEP 等价；这种一致性由服务端负责。** 当前仅检查几何，不自动核验图纸尺寸符合性。装配体或多实体返回会失败。

## 失败、时限和重试

失败返回非 200 状态码；例如 422 表示无法重建输入、503 表示推理服务不可用。不要在错误响应泄露密钥、路径或完整环境。本地只展示状态码和简短说明，不转发响应正文。

本地默认网络读超时 600 秒，可通过 `.env` 调整；超过时限任务失败。该值是 HTTPX 的网络阶段超时，不是整个工作流的绝对总时限。后续 STEP 导入有独立 90 秒进程时限。用户可手动重新运行；每次输出保存到新的执行目录，成功后追加版本。

连接断开不保证远端终止 GPU 计算。若需要可靠的远端取消、长任务进度和断点恢复，下一版应扩展创建任务、查询状态、取消任务的异步接口；当前客户端为同步响应协议。

## 服务端需要完成的最小流程

1. 验证文件、单位、消息长度和身份，建立独立任务目录。
2. 将图纸与要求送入已部署模型，得到受约束 CAD 表达或代码。
3. 在隔离环境执行/解释 CAD 表达，限制网络、文件、时间和内存；不要在 API 主进程直接 exec 模型代码。
4. 用 CAD 内核检查实体并导出 STEP；确保源码与实体来自同一次生成。
5. 将两个文件打包返回；失败返回明确 HTTP 状态。

本地 `backend/tests/test_api.py::test_remote_contract_with_mock_transport` 使用预先构造的真实 STEP 验证传输与导入链路，可作为契约示例；它不是服务器模型实现。
