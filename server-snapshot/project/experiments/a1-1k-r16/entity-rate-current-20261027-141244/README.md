## 统计口径

- 固定原测试集 50 个编号，其中原本确认标准模型有效的 44 个参与本次实体生成率统计；原来无效的 6 个不参与推理、不进入分母。并非只重跑 10 个失败样本。
- 同一已合并 SFT 模型，16384 token，600 秒生成软时限，最多一次自动修复，CAD 执行墙钟上限 90 秒。
- 使用真实线上 Agent，通过现有 GPU 共享准入检查，每次生成后释放模型进程。不发送参考代码、参考 STEP、人工修复代码。
- 首次成功数、自动修复新增成功数与最终成功数分别统计。部分完成时不发布最终百分比。
- 排队超时或服务繁忙重试，不作为几何失败。重复模型服务错误单独记录为运行失败，最终报告必须披露，不能混称几何错误。
- 只评估实体有效性，不以此代替图纸、尺寸或外形准确率；本轮不运行昂贵的 IoU 比较。
- 基线为 34/44。生成和 CAD 时间预算、修复流程均已改变，差异属于整个流程变化，不是新增训练的效果。
- 这批样本已用于诊断和修复策略开发，因此新成绩是固定回归集结果，不是新的独立泛化评估。

## 状态与产物

- `progress.json`：已完成数、当前编号、首次成功数、最终成功数、待处理编号。
- `test-*.json`：每个样本的真实尝试记录，包含诊断和对应服务器 run_id。
- `test-*.py` / `test-*.step`：成功样本的模型生成结果；源码不会在宿主执行。
- `protocol.json`：输入编号、排除编号、参数、原始评估与服务源码哈希。
- `summary.json`：仅在全部 44 个样本结束后生成，包含相对旧结果的新成功和退步编号。
