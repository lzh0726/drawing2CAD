## 两类工作必须分开统计

人工修复用于验证正确的几何构造。本次检查了三个原始二维图纸，并使用配对参考代码补齐未标注的孔径、壁厚、圆弧等参数。因此，这是**参考标签辅助的离线重建**，不是模型独立识图后的成功结果，不能把原来的 34/44 改成 37/44。

在线 Agent 则只接收原始图纸、用户要求、失败代码与隔离执行器产生的诊断，不访问这三个样本的标准 STEP 或参考代码。

源码为本目录三个 `*-repaired.py`。只能交给 CAD 隔离执行器运行；不应直接在宿主执行模型来源代码。

## 自动修复实现

1. 模型初次生成代码。每次 GPU 使用继续遵循原空闲/共享准入规则。
2. Bubblewrap 中执行代码，检查单个有效实体、正体积和 STEP 导出。
3. CAD 失败后，在另一个受限 CPU 沙箱中按顶层语句重新执行，定位首次无效几何或异常。涉及循环时，行号对应该顶层语句，而非逐次循环内部的精确行号。
4. 获取失败行、操作、实体数量、OpenCascade 错误，并添加针对相交轮廓、自交线框等问题的提示。完整诊断保存在该请求的 `trace.json` 中。
5. 把原图、失败代码和诊断反馈给模型，要求保留图纸尺寸和特征，缺少信息时请求补充，不允许通过任意删特征掩盖问题。
6. **最多修复一次**。有效则返回新模型，仍失败则结束；已有成功版本不覆盖。

单独线框有效，不代表其组成的面有效。诊断会检查面和线框的内核错误；它提供修复方向，但不会自行保证图纸符合性。

## 代码位置

- `tools/cad-runtime/cad_diagnostics.py`：隔离内部的逐语句诊断。
- `tools/cad-runtime/research_worker.py`：受限诊断入口，沿用安全过滤和资源约束。
- `server/research_sandbox.py`：诊断 JSON 的返回解析。
- `server/bubblewrap_executor.py`：失败后的隔离诊断调用，超时则返回诊断不可用。
- `server/app.py`：诊断写入请求记录，并加入下一次修复提示。
- `backend/app/worker.py`：将 CAD 失败与需要补充信息区别于连接错误。

线上目前使用 Bubblewrap；本次没有扩展 Docker 执行器的详细几何诊断。

部署配置为 `CAD_MAX_REPAIRS=1`。单次模型生成仍最多 600 秒，推理子进程含加载最多 720 秒，单次 GPU 排队最多 300 秒。由于一次请求可能包含两轮生成，本地 `CAD_REMOTE_TIMEOUT` 配套设为 2400 秒；这只是等待上限，不代表每次请求都会耗时这么久。若暂时关闭自动修复，可将服务器的 `CAD_MAX_REPAIRS` 恢复为 0 并在空闲时重启项目网关。

## 测试边界

本地回归：32 项通过、1 项 Docker 测试按环境条件跳过。

服务器集成验证使用**固定的首次失败回答和人工修复回答**，搭配真实 CPU CAD 沙箱，检查反馈传递、保留原图和失败代码、STEP 输出以及最多一次修复的限制。这验证流程实现，不测量真实模型的修复成功率。

精确布尔 IoU 若超出隔离资源限制，会保留失败事实，另行进行带固定种子的体积采样比较。采样结果只用于辅助一致性验证，不能声称严格几何等价，更不能替代正式测试集指标。

没有 GPU 推理或训练，没有修改原始评估文件。真实模型的自动修复成功率需要后续在固定测试集上独立评估。
