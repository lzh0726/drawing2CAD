6 个截断回答都含重复建模片段、达到配置中的 2048 token 上限且没有完整收尾，证据强烈支持输出预算耗尽。这里统计的是保存文本重新编码的 token 数，不是原生成器保存的 finish_reason，因此不声称已读取原始停止原因。

三项 invalid_or_multiple_solids 已细分为单实体无效，不是多实体。具体是哪条边、面或轮廓导致无效，仍需进一步 BRep 子形状分析；本次不把自交、相切等猜测写成已证实结论。

超时跟踪只定位到布尔合并操作。没有放宽 CPU 限制或证明其数学上永不收敛，也不能排除共享服务器负载的影响。120 秒运行带行号跟踪，不作为性能基准。

## 参考程序与标准 STEP 的额外问题

10 份参考程序中 9 份可在当前隔离执行环境生成有效实体。
test-00966577 的参考程序生成 1 个 isValid=false 的实体，体积约 0.0235600。
对应标准 STEP 导入检查有效，体积约 0.0244041。
这表明当前环境下参考代码与标准 STEP 的有效性不一致；具体是转换标签问题还是 CAD 内核版本敏感性，尚不能定论。
不删除该测试项，也不调整原 44 个有效真值的分母。该样本自己的预测仍存在独立的重复与截断失败。

## 后续优先级

1. 在独立实验中细分输出截断、缺少 result、语法错误等状态，避免统一报语法错误。缺失闭合围栏可改进诊断，但不能将残缺代码自动当成成功。
2. 先分析重复生成，再设计输出预算对照。单纯把 2048 提高到 4096 可能只会延长重复，不保证修复。需要 GPU 的新生成实验本次未运行。
3. 对 3 个无效实体做边、面、轮廓级定位，并补充几何反馈；本次没有自动修改其代码。
4. 将 test-00966577 的标签问题单独登记，在复制的数据集上研究版本兼容与标签修正，保留原始数据和测试集合。
5. 超时项继续保持资源隔离，先检查布尔操作输入与退化几何，再决定是否调整执行预算。
